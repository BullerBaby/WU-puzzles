Load your own game (paste JSON)

Paste a game as JSON below, then click Load game. The easiest start is Use current as template: it dumps the game you're viewing into the box so you can edit it. Custom games are saved in your browser (localStorage) and added to the dropdown. Single game or a JSON array of games both work. Required fields: title, board, fighters, steps. See the docs below for the full data shape.

Notation reference

Coordinates

Files a–k left to right, ranks 1–9 from your edge (rank 1) up to opponent's (rank 9).

Fighters

Yours UPPERCASE, opponent lowercase. ↑F = inspired. Leaders have thicker outline.

Actions

- move   > charge   x attack   ~ disengage   ^ guard   : teleport   @ end-hex

Attack results

×N damage   † slain   ! crit   0 miss   /N defender saves

Dice

Attack: H hammer, S sword, C crit, - blank.
Defence: D dodge, Sh shield, C crit, - blank.

Hands

hand: { me: { objectives: [...], power: [...] }, opp: { objectives: N, power: N } }. Arrays show as named chips, numbers as face-down placeholders.

Power step events

Per step, powerStep: [{ side, type, name, kind?, target? }]. type: card | ability | reaction. kind: upgrade | gambit.

Action tokens

Per step, tokens: { FighterCode: ['charge', 'guard'] }. Built-in types: move, charge, guard, stagger, cleave, defence. Any other string renders with its first letter on a neutral chip. Clear tokens at end-of-round.

Features

Per step, features: [{ type, hex, label?, delved? }]. Types: treasure (use label: "1"–"5") and aqua (Aqua Ghyranis). Hexes with feature tokens get a warm tint so they stand out. Set hex: null when off-board. Add delved: true to outline the token in red (the number still shows inside).

Polls

Per step, poll: { question?, options: [...], actual? }. A vote panel appears when a step has a poll; clicking an option adds 1 vote. Tallies are saved in the browser's localStorage per game-id + step-index, so they persist across reloads but stay local to that device (no server, no cross-device sync). Optional actual index marks which option was played — gets a green ✓ once votes exist.

Fighter cards & stats

Each warband panel (opponent's above the board, yours below) shows fighter cards alongside the hand. Cards show wounds taken and upgrades; hover for full stats and attack profiles. Per fighter, optional fields: move, wounds, glory, save: { dice, type } (type: block or dodge), attacks: [{ name, range, dice, damage, type, cleave?, note? }] (attack type: sword or hammer), attacksInspired: [...].

Upgrades

Per step, upgrades: { FighterCode: ['Upgrade name', ...] }. Shown as chips on the fighter card. Persists per step like tokens — repeat in each step the upgrade is in play.

Warscroll abilities

Game-level abilities: { me: ['Ability name', ...], opp: [...] } lists each warband's named abilities. Per step, abilitiesUsed: { me: ['Ability name', ...], opp: [...] } marks which have been used so far. Shown as chips with a side-colored round token; when used, the token is removed and the name is struck through.

Warbands registry

Define a warband once in the WARBANDS object (at the top of the script): { id: { name, fighters: { code: { label, name?, ... } }, abilities: [...] } }. A game can then use warbands: { me: 'id-a', opp: 'id-b' } in place of inlining fighters and abilities. Inline fighters[code] and abilities still work and merge over the warband definition, so you can override a single fighter's stats per game without copying the whole warband.

Step inheritance (diff mode)

A step can declare its state as state: { ... } (full snapshot — old style) or diff: { ... } (merged onto the previous step's expanded state). In diff mode, OBJECT fields (positions, wounds, tokens, upgrades, abilitiesUsed, hand) deep-merge — only the keys you specify change. ARRAY fields (slain, inspired, features) and glory replace when present. powerStep never inherits (defaults to []). Use null as a field value to reset to default — e.g. tokens: null at end of round.

Activations & glory

Each side has 4 activation tokens shown in the panel header. Per step, activationsUsed: { me: N, opp: N } sets how many have been used so far — the right-most tokens go hollow. Reset with activationsUsed: null at end of round. The golden coin next to the tokens reads from state.glory[0] (yours) and state.glory[1] (opp). The current round number shows centred at the top of the board card.

Decks & plot cards

Per game, decks: { me: { pair, plots }, opp: { pair, plots } }. pair is a string like the deck pair name (e.g. "Hunter's Cunning / Stalking Shadows"); plots is an array of up to 2 plot-card names. Shown in the warband panel header below the side label — deck pair as italic text, plot cards as small side-colored chips.

Game schema

{ title, description?, board, round, boardRotation?, warbands?: { me, opp }, fighters?: {...}, abilities?: { me, opp }, decks?: { me, opp }, steps: [{notation, title, explanation, dice?, anim?, poll?, state | diff}] }. State fields: positions, wounds, slain, inspired, glory, tokens, upgrades, abilitiesUsed, activationsUsed, features, hand, powerStep.

Board rotation

boardRotation: 180 mirrors special-hex positions, or press ↻ / R.

Single-file replay tool. Built-in games live in the GAMES object at the top of the script; custom games loaded via the panel above are stored in your browser. Drop the file on any static host (GitHub Pages, Netlify, Cloudflare Pages). Board shapes and special-hex positions are best-effort approximations — adjust to match your physical boards.
